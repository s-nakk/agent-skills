# プロジェクト開発ルール

## ルールの適用と読み分け

共通の作業判断・コーディング規約・サブエージェント利用条件は、Codex が読む GLOBAL の `AGENTS.md` を正本とする。このファイルにはプロジェクトの運用・追加条件だけを置き、GLOBAL の本文を再掲しない。別 agent の `CLAUDE.md` は機械的に同期しない。

以下の補助規約もこのファイルの一部であり、該当操作の前に読む。参照はこのファイルがあるプロジェクトルートを基準とする。source・仕様・test は作業対象 branch のものを読む。

| 着手条件 | 読む補助規約 |
|---|---|
| プロジェクトでの作業開始・完了条件の判断 | [運用選択とプロジェクトの正本](.codex/rule-reference/settings.md) |
| 変更依頼、設計承認、Issue 操作、Worktree、検証・commit・push・PR | [作業フロー](.codex/rule-reference/workflow.md) |
| 独立レビューの準備・起動・指摘対応・再レビュー | [独立レビュー](.codex/rule-reference/review.md) |

補助規約が見つからない場合は、対象操作を止めて欠けたパスを報告する。無関係な read-only 調査は継続できる。個人ローカルの規約変更へ製品変更向けの Issue・設計承認を一律に要求しない。

## 実装コメント

- 各論理ブロックの直前へ、そのブロックが必要な理由・守る契約・後続へ渡す前提を日本語コメントで記す
- 対象は条件分岐、反復、例外処理、入力検証、データ変換、外部 I/O、状態変更、永続化、処理段階の切り替え。コードを日本語へ言い換えるだけのコメントにしない
- コメントの表記は GLOBAL のコーディング規約に従う。導入先に異なるコメント方針があれば、既存方針との判断を `settings.md` に記録する

## 作業種別ごとの完了条件

Issue・作業場所・設計承認・独立レビュー・Git の完了地点は `settings.md` の選択を使う。以下は仕様と検証の違いであり、選択していない Issue・commit・push・PR を追加しない。

| 作業 | 仕様と検証 |
|---|---|
| 説明、状態確認、read-only 調査、review-only | 根拠付き報告 |
| 個人ローカルのルール・索引・メモ | 差分と参照の確認 |
| 文書変更 | 契約変更なら受け入れ条件を更新 |
| バグ修正 | 再現テストで期待する理由の Red を確認 |
| 新機能、API、DB、認証、認可 | 受け入れ条件を含む仕様と Red を確認 |
| 振る舞い・環境契約を変える設定、infra、CI/CD | 契約を明文化し、test 可能なら Red を確認 |
| 振る舞いを変えない refactor | 変更前後の Green を確認 |
| 緊急 hotfix | 再現を優先。不可能なら理由・事後補完の記録先・期限を残す |

## プロジェクトでの委任条件

設計承認を採用した変更では、承認前に委任できるのは read-only の調査だけ。承認後も採用した仕様・編集範囲に限定し、設計判断・統合は親が担当する。プロジェクトの契約と運用選択は委任先にも適用する。

## 実行品質ガード

- 編集前に対象ファイル全体を読む
- 同種の失敗が2回続いたら同じ再試行を止め、原因仮説と手段を変える
- 複数ターンの作業では、節目ごとにユーザーの直近の依頼と元の目的を読み直す
- 変更提示前に、依頼、受け入れ条件、差分、検証結果を照合する

## 完了報告

結果と変更した契約、再現と検証結果、独立レビューの担当・指摘・対応・再レビュー、残る risk と cleanup を簡潔に報告する。設計承認を使った場合は承認版・設計差分・追加承認、Issue・Git・外部環境を使った場合はそれぞれの状態を加える。非該当の項目を埋めない。
