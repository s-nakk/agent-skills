# 運用選択とプロジェクトの正本

## 適用範囲と版

配布版: 2。導入日、GLOBAL と Project の適用範囲、GLOBAL が有効である確認、規約の共有・ローカルの選択を記録する。通常作業では初回質問を繰り返さない。

## 運用選択

以下を、それぞれ既存規約・ユーザー回答のどちらで確定したかとともに記録する。

- Issue: 不使用 / 必要時 / 必須。必要時なら具体的な適用条件
- 設計承認: 対象条件、形式、保存先。Issue なしなら変更名と版で識別する
- Git 完了地点: ローカル変更 / commit / push / draft PR。Git がなければ非該当
- 作業場所: checkout / 専用 Worktree。Worktree なら作成場所の解決方法、base、規約の参照方法、依存準備と撤去条件
- 独立レビュー: 対象条件、利用可能な担当・起動と同じ担当の再開方法、read-only 制限、入力方式、利用する Skill があればその適用条件
- 保存範囲: プロジェクトで共有 / この端末だけ。追跡・ignore の実際の状態
- 既存規約と原本の差: GLOBAL に対するプロジェクトの明示的な例外、保持した独自条件、コメント方針の差があればその判断

## 正本・実行環境・検証

目的・上位要件・長期仕様・設計・言語固有ルール・ドキュメント索引の実在する参照先を記録する。存在しない原本を要求しない。source、migration、API 契約、manifest、lockfile、CI・deploy の入口、リリース状態は対象プロジェクトの現物から確認する。

パスはプロジェクトルート基準。Windows ネイティブ・WSL・macOS の実行環境、必要なシェル・ツール、確認できた検証コマンドと適用条件を記録する。共通コマンドは一度だけ、異なる場合だけ環境別に書く。実行済み・資料で確認済み・未確認を区別する。secret 値や元端末のホームを保存しない。

## Skill と運用選択

Skill は選択した条件に合う場合だけ使う。Issue なし・承認不要の変更へ Skill の既定から Issue や設計ゲートを追加しない。レビューのために Git の完了地点を引き上げない。導入済みであることは採用済みであることを意味しない。

端末変更だけで運用選択をリセットせず、実行不能になった項目だけ見直す。規約ファイルの配置先と有効な入口が両立しない場合は、対象と変更案を示してから解決する。
