# プロジェクトの開発方針

このファイルは導入時に決めた運用の正本。通常の開発では保存済みの選択を使い、初回の質問を繰り返さない。ユーザーが変更を依頼した場合か、環境変化で実行不能になった項目だけ見直す。

導入日と共通規約の配布版を記録する。

## 運用選択

Issue、設計承認の条件と形式、Git の完了地点、作業場所、独立レビューの条件と実行方法・入力、保存範囲を記録する。それぞれ既存規約・ユーザー回答のどちらで確定したかを添える。Git がない項目などは非該当と明記する。

## プロジェクトの正本と検証

目的・仕様・設計・言語固有ルールの実在する参照先、manifest と lockfile、確認できた検証コマンドと適用条件を相対パスで記録する。未確認のコマンドを創作しない。secret 値や端末固有のホームパスを保存しない。

Windows ネイティブ・WSL・macOS のうちプロジェクトで利用する環境と、必要なシェル・ツールを記録する。共通で使えるコマンドは一度だけ書き、異なる場合だけ環境別に分ける。実行済み・資料で確認済み・未確認を区別する。端末変更だけで運用選択をリセットしない。

## Skill の適用

Skill は選択された条件に合う場合だけ使う。Issue なし・承認不要の変更へ、Skill の既定から Issue や設計ゲートを追加しない。導入済みであることは採用済みであることを意味しない。

## 通常作業の完了条件

目的・範囲・完了条件を揃え、選択に従って実装・検証・必要なレビューを進める。Git の完了地点を越える操作、ready・merge・auto-merge・本番変更は、その操作への別の明示指示が必要。
