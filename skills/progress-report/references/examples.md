# 出力例（匿名化済み）

実プロジェクトの報告を基に、固有名詞を置き換えたもの。

## 例 1: 改善・新機能だけで他セクションを省略する例（2026-04-21 の作業をベースに整形）

入力: 「2026-04-20 23:20 〜 2026-04-21 09:30 の進捗報告」

この期間はバグ修正もその他も無く、すべて改善・新機能。空のセクションは見出しごと省略する。

出力:

```
進捗報告（4/20 23:20 〜 4/21 9:30）

◆ 改善・新機能
• 権限周りで提供いただいた要件を確認し、設計、DBスキーマ、既存実装に反映
• 社内管理者が テナント画面からテナント管理者を招待するフローを実装（権限変更を監査ログに記録）
• テナント新規作成画面を実装
• 拠点管理画面を実装（3 拠点 + 共通の拠点一覧、公開キーの発行・失効運用 UI つき）
• FAQ データ基盤を整備（ライフサイクル状態 / カテゴリ / 多言語翻訳連携 / 非同期ジョブ管理 用のテーブル一式）
• FAQ 管理画面を順次構築（一覧 → 新規作成ドロワー → リッチテキスト編集エディタ統合）
• FAQ 回答内のリンクを許可済みプロトコルのみに制限する安全検証を追加（危険な URL を保存時に拒否）
• AI の思考深度を外部設定で調整可能にし、応答品質と速度のチューニング余地を確保
• staging 環境へのCI/CD構築(途中)
```

この例の特徴:
- バグ修正・その他が無いのでそれぞれセクションごと省略（振り分けルール）
- 「提供いただいた要件を確認し」（ルール 2）
- 機能名のみで UI 手順は省く（ルール 3）
- `(途中)` の付与（ルール 4）
- 次回予定なし（ルール 5）
- 内部実装語なし（ルール 1 / 6）

## 例 2: 3 セクションすべてが揃う例（2026-05-23 の作業をベースに整形）

入力: 「5/23 1:05〜9:45 の進捗報告」

バグ修正 → 改善・新機能 → その他 の順。手動 QA チェックリストの拡充は機能でもバグ修正でもないので「その他」へ。

出力:

```
進捗報告（5/23 1:05 〜 9:45）

◆ バグ修正
• 2段階認証で「この端末を30日間信頼する」を選んでも再ログイン時に認証コードを求められる不具合を解消
• 一覧画面の絞り込みで選択肢が背面に隠れて選べなくなる不具合を全画面で解消

◆ 改善・新機能
• 会話分析画面を刷新（FAQ化をおすすめする順に質問の話題を並べたグラフと、総会話数・未回答件数などのサマリへ統合）
• チャット内の予約・電話案内リンクを、読みやすいリスト型ボタンへ刷新
• 各管理画面の入力まわりを整備（記入例の表示、並び替えラベルを「昇順／降順」へ統一など）

◆ その他
• 各管理画面の手動動作確認チェックリストを画面別に拡充（支払い・拠点設定・部門・担当者・設備・よくある相談・予約・公開チャット）
```

この例の特徴:
- バグ修正 → 改善・新機能 → その他 の 3 セクションに分けた（振り分けルール）
- 手動 QA チェックリストは機能でもバグ修正でもないので「その他」へ
- バグ報告は経緯を書かず「〜を解消」だけ（ルール 2 の例外）
- 各行が 1 行で読み切れる短さ（ルール 7）
